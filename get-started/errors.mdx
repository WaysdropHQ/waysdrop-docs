# Errors

Waysdrop returns a consistent error envelope for HTTP exceptions (via the global exception filter).

## Error envelope

All errors use this structure:

```json
{
    "statusCode": 500,
    "method": "POST",
    "timestamp": "2026-01-24T12:34:56.789Z",
    "path": "/api/request",
    "url": "https://api.waysdrop.com/api/request",
    "message": "Internal server error",
    "environment": "staging"
}
```

**Field meanings**

- `statusCode`: HTTP status code
- `method`: HTTP method
- `timestamp`: ISO timestamp when the error was generated
- `path`: request path without query string
- `url`: full request URL (includes query string)
- `message`: human-readable error message
- `environment`: server environment label

## Error format

Routes under `/v2/` return RFC 9457-style problem bodies. Switch on `code`, not on the message.

```json
{
    "type": "urn:waysdrop:problem:VALIDATION_FAILED",
    "title": "Bad Request",
    "status": 400,
    "detail": "url must be a URL address; enabledEvents should not be empty",
    "instance": "/v2/webhooks/endpoints",
    "code": "VALIDATION_FAILED",
    "correlationId": "0f9a6c1e-7b8d-4c2a-9e51-3d2f1a7b6c93",
    "statusCode": 400,
    "message": "url must be a URL address; enabledEvents should not be empty",
    "details": { "code": "VALIDATION_FAILED" },
    "errors": [
        { "field": "url", "message": "url must be a URL address" },
        { "field": "enabledEvents", "message": "enabledEvents should not be empty" }
    ]
}
```

- `code`: stable machine-readable code (also in `details.code`).
- `errors[]`: per-field validation messages (validation errors only).
- `correlationId`: quote it to support. It is also returned in the `X-Correlation-Id` response header.

Routes under `/api/` keep the envelope above; `details.code` carries the code where one exists, for example `ADDRESS_PIN_MISMATCH`.

## Idempotency

Writes that create records or move money under `/v2/` take an `Idempotency-Key` header (1 to 255 visible ASCII characters; use a UUID). Where an endpoint requires it, a missing key is `400 IDEMPOTENCY_KEY_REQUIRED`.

- A key is scoped to your account and API key, and a completed response is replayed for 24 hours. A replay carries `Idempotent-Replayed: true`.
- Reusing a key with a different request is `409 IDEMPOTENCY_KEY_REUSED`.
- Retrying while the first request is still running is `409 IDEMPOTENCY_REQUEST_IN_PROGRESS` with `Retry-After: 2`. Retry after that delay with the same key.
- `400 IDEMPOTENCY_KEY_INVALID` means the key is malformed; `409 IDEMPOTENCY_RESPONSE_UNAVAILABLE` means the stored result is no longer available.

On `POST /api/request`, use `externalReference` instead: repeating it returns the stored delivery.

## Pagination

List routes under `/v2/` use keyset pagination: pass `limit` and the opaque `cursor` from `page.nextCursor` of the previous page.

## Rate limits

- A global limit of 180 requests per minute per IP applies. Responses carry `X-RateLimit-*` headers, and `429` responses carry `Retry-After`.
- Some routes have lower limits, documented on the route.
- Public keys (`wsp_pub_…`) are limited to 60 requests per minute per key and IP.
- Quotas are reported in `details.quota` (see below).
- `402` means API usage is unpaid: top up your wallet.
- In maintenance and read-only mode, writes answer `400`.
- Unknown request body fields are stripped.
- Staging keys work only on staging, live keys only on live.

## API key auth errors

### Missing API key

**Status**: `401 Unauthorized`  
**Message**: `API key is required`

```json
{
    "statusCode": 401,
    "method": "GET",
    "timestamp": "2026-01-24T12:34:56.789Z",
    "path": "/api/countries",
    "url": "https://api.waysdrop.com/api/countries",
    "message": "API key is required",
    "environment": "live"
}
```

### Invalid API key format

API keys must match: `wsp_(live|staging)_[a-f0-9]{64}`

**Status**: `401 Unauthorized`  
**Message**: `Invalid API key format`

```json
{
    "statusCode": 401,
    "method": "GET",
    "timestamp": "2026-01-24T12:34:56.789Z",
    "path": "/api/countries",
    "url": "https://api.waysdrop.com/api/countries",
    "message": "Invalid API key format",
    "environment": "live"
}
```

### Invalid or inactive API key

**Status**: `401 Unauthorized`  
**Message**: `Invalid API key`

```json
{
    "statusCode": 401,
    "method": "GET",
    "timestamp": "2026-01-24T12:34:56.789Z",
    "path": "/api/countries",
    "url": "https://api.waysdrop.com/api/countries",
    "message": "Invalid API key",
    "environment": "live"
}
```

## Rate limits / quota

### API quota exceeded

**Status**: `429 Too Many Requests`  
**Message**: `API quota exceeded`

```json
{
    "statusCode": 429,
    "method": "GET",
    "timestamp": "2026-01-24T12:34:56.789Z",
    "path": "/some/path",
    "url": "https://api.example.com/some/path?x=1",
    "message": "API quota exceeded",
    "details": {
        "message": "API quota exceeded",
        "error": "Too Many Requests",
        "quota": {
            "limit": 123,
            "remaining": 0,
            "resetAt": "2026-01-24T12:34:56.789Z",
            "resetIn": 42
        }
    },
    "environment": "staging"
}
```

## Business errors

### Insufficient balance

Returned when wallet debit fails (e.g., creating a delivery request).

**Status**: `422 Unprocessable Entity`  
**Message**: `Insufficient balance`

```json
{
    "statusCode": 422,
    "method": "POST",
    "timestamp": "2026-01-24T12:34:56.789Z",
    "path": "/api/request",
    "url": "https://api.waysdrop.com/api/request",
    "message": "Insufficient balance",
    "environment": "live"
}
```

### Payment required

Returned when wallet debit fails for api usage

**Status**: `402 Payment Required`  
**Message**: `Insufficient wallet balance for API usage`

```json
{
    "statusCode": 402,
    "method": "POST",
    "timestamp": "2026-01-24T12:34:56.789Z",
    "path": "/api/request",
    "url": "https://api.waysdrop.com/api/request",
    "message": "Insufficient wallet balance for API usage",
    "environment": "live"
}
```

### Validation errors

Request validation errors are returned as `400 Bad Request` and the message contains a semi-colon separated list.

```json
{
    "statusCode": 400,
    "method": "POST",
    "timestamp": "2026-01-24T12:34:56.789Z",
    "path": "/api/request",
    "url": "https://api.waysdrop.com/api/request",
    "message": "destinationContactEmail: must be an email; packagesId: each value in packagesId must be a UUID",
    "environment": "live"
}
```

## Success responses

Most successful API responses use:

```json
{
    "success": true,
    "message": "Pricing fetched successfully",
    "data": {}
}
```

Some endpoints respond with `204 No Content` (no JSON body).

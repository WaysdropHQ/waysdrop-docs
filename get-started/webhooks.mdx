# Webhooks

Waysdrop sends webhooks for delivery and payment events. Webhooks are delivered asynchronously, at least once, and retried on failure.

You manage endpoints through the API ([Webhook endpoints](/api-reference/webhooks)): each account can have several endpoints, and each endpoint subscribes to the events it wants.

## Environments

Webhooks are scoped to the environment of the API key that created the endpoint:

- Live: `https://api.waysdrop.com` (`livemode: true`)
- Staging: `https://staging-api.waysdrop.com` (`livemode: false`)

There is no test mode on live: staging is the test environment.

## Request

Waysdrop POSTs the event as UTF-8 JSON to your `https` endpoint URL.

| Header                      | Value                                                                        |
| --------------------------- | ---------------------------------------------------------------------------- |
| `Content-Type`              | `application/json`                                                           |
| `User-Agent`                | `Waysdrop-Webhooks/2.0`                                                      |
| `Waysdrop-Event-Id`         | `evt_<uuid>`, equal to the body `id` (your dedupe key)                       |
| `Waysdrop-Event-Type`       | For example `delivery.collected`                                             |
| `Waysdrop-Delivery-Id`      | Identifies this event-to-endpoint delivery; stable across retries            |
| `Waysdrop-Delivery-Attempt` | `1`, `2`, …                                                                  |
| `Waysdrop-Signature`        | `t=<unix seconds>,v1=<hex>[,v1=<hex>]`                                       |

## Event envelope

```json
{
    "id": "evt_0193b2f4-1c2d-7a3b-9c4d-5e6f7a8b9c0d",
    "type": "delivery.collected",
    "apiVersion": "2026-11-25",
    "createdAt": "2026-11-25T10:00:00.000Z",
    "livemode": true,
    "account": { "id": "uuid" },
    "sequence": 3,
    "data": {
        "object": { "object": "delivery", "id": "uuid" },
        "previous": { "status": "..." }
    }
}
```

- **At least once.** Store `id` and ignore a repeat.
- **Ordering is best effort.** `sequence` increases per resource (`data.object.object` + `data.object.id`). Keep the highest value you applied per resource and ignore anything lower.
- `data.object` is the full snapshot at the time of the event. `data.previous` holds only the fields that changed, when known.
- **Money** is always `{ "amountMinor": "150000", "currency": "NGN" }`: integer minor units as a decimal string (it can exceed 2^53). Parse it with a big-integer or decimal type, never a float. See [Money and currencies](/get-started/money-and-currencies).
- Payloads never contain proof, collection or delivery codes, proof images, IP addresses or courier contact details.

## Verify the signature

```
signed_payload = t + "." + rawBody
v1             = lowercase hex( HMAC-SHA256( key = endpoint secret "whsec_…", message = signed_payload ) )
```

Verify in this order:

1. The header must be present and parse as comma-separated `key=value` pairs. `t` is 1 to 12 digits; keep each `v1` that is 64 lowercase hex characters; ignore other keys.
2. Reject if `|now − t|` is more than 300 seconds.
3. Compute the HMAC over the **raw request body bytes** with every secret you have configured, and compare against every `v1` in constant time.
4. Parse the body as JSON.

Never verify a re-serialised body: make your framework expose the raw bytes.

```js
import crypto from "crypto";

export function verifyWaysdropWebhook(rawBody, header, secrets, toleranceSec = 300) {
    const parts = header.split(",").map((p) => p.split("="));
    const t = parts.find(([k]) => k === "t")?.[1];
    const sigs = parts.filter(([k]) => k === "v1").map(([, v]) => v);
    if (!t || !/^\d{1,12}$/.test(t) || sigs.length === 0) return false;
    if (Math.abs(Date.now() / 1000 - Number(t)) > toleranceSec) return false;

    const signedPayload = `${t}.${rawBody}`;
    return secrets.some((secret) => {
        const expected = crypto.createHmac("sha256", secret).update(signedPayload).digest("hex");
        return sigs.some(
            (s) => s.length === expected.length && crypto.timingSafeEqual(Buffer.from(s), Buffer.from(expected)),
        );
    });
}
```

### Secrets and rotation

A secret looks like `whsec_` plus 43 characters. It is shown once, when you create the endpoint or rotate its secret. When you rotate, the previous secret keeps signing for `expiresInSeconds` (default 86400, max 604800, `0` stops it at once), and `Waysdrop-Signature` carries two `v1` values. Configure both secrets during that window.

## Your response and retries

| Your response                                                   | Result                                                                    |
| --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Any `2xx` within 10 seconds                                     | Success                                                                   |
| `410 Gone`                                                      | Endpoint disabled (`disabledReason: "gone"`), no more attempts            |
| Any other 3xx, 4xx or 5xx, a timeout, or a DNS, TLS or connect error | Retried                                                              |

- Redirects are not followed.
- Retries use exponential backoff with jitter (waits of up to 1 min, 5 min, 30 min, 2 h, then 6 h) for up to 3 days from the first attempt. After that the delivery is `failed`.
- An endpoint that fails continuously for 3 days is disabled (`disabledReason: "failing"`). Re-enable it with `PATCH /v2/webhooks/endpoints/{id}` and `{"status":"enabled"}`, then replay what you missed.
- At most 4 requests are in flight to one endpoint at a time.
- Endpoint URLs must be `https`, without credentials, on port 443 or 1024 to 65535. Loopback, private, link-local and cloud-metadata addresses are refused.
- You can have at most 16 endpoints.

## Event types

Subscribe with `enabledEvents` (up to 40 types, or `["*"]` for all). `ping` is only sent on request.

| Type                          | Object             | Sent when                                                  |
| ----------------------------- | ------------------ | ---------------------------------------------------------- |
| `delivery.created`            | `delivery`         | A delivery was created through the API                     |
| `delivery.assigned`           | `delivery`         | A courier accepted the delivery                            |
| `delivery.collected`          | `delivery`         | The courier collected the package                          |
| `delivery.in_transit`         | `delivery`         | The courier is on the way to the drop-off                  |
| `delivery.delivered`          | `delivery`         | The delivery was completed                                 |
| `delivery.cancelled`          | `delivery`         | The delivery was cancelled                                 |
| `delivery.failed`             | `delivery`         | The delivery failed and will not be completed              |
| `payment.succeeded`           | `payment`          | A payment succeeded                                        |
| `payment.failed`              | `payment`          | A payment failed                                           |
| `payment.refunded`            | `payment`          | A refund was processed                                     |
| `ping`                        | `ping`             | A test event you requested                                 |

The schema also lists `delivery.partially_delivered`, `delivery.stop.arrived`, `delivery.stop.completed`, `delivery.stop.failed` and `delivery.plan.changed`. Those belong to multi-stop deliveries, which the Partner API does not create, so you will not receive them.

### Delivery object

`delivery.*` events carry:

```json
{
    "object": "delivery",
    "id": "uuid",
    "trackingId": "WD-P2P-7Q2K9X",
    "externalReference": "partner-order-1001",
    "type": "P2P",
    "status": "PACKAGE_COLLECTED",
    "routeType": "INTER_CITY",
    "pickup": { "label": "Warehouse", "addressLine1": "12 Example Street", "city": "Ikeja", "state": "Lagos", "countryCode": "NG", "lat": 6.6018, "lng": 3.3515, "contactName": "Dispatch desk", "contactPhone": "+2340000000000" },
    "dropoff": { "addressLine1": "3 Sample Close", "city": "Lekki", "state": "Lagos", "countryCode": "NG", "lat": 6.6018, "lng": 3.3515 },
    "courier": { "id": "uuid" },
    "fee": { "amountMinor": "1250", "currency": "USD" },
    "total": { "amountMinor": "1500", "currency": "USD" },
    "orderId": null,
    "checkoutSessionId": null,
    "createdAt": "2026-11-25T10:00:00.000Z",
    "assignedAt": "2026-11-25T10:00:00.000Z",
    "collectedAt": "2026-11-25T10:30:00.000Z",
    "deliveredAt": null,
    "updatedAt": "2026-11-25T10:30:00.000Z"
}
```

`pickup` and `dropoff` carry the full address projection (`id`, `label`, `addressLine1`, `addressLine2`, `floor`, `city`, `state`, `region`, `country`, `countryCode`, `zipCode`, `lat`, `lng`, `contactName`, `contactPhone`, `contactEmail`, `note`); the example is shortened.

### Payment object

`payment.succeeded`, `payment.failed` and `payment.refunded`:

```json
{
    "object": "payment",
    "id": "uuid",
    "reference": "TXN-0001",
    "kind": "payment",
    "status": "SUCCESS",
    "amount": { "amountMinor": "2548", "currency": "USD" },
    "orderId": null,
    "deliveryId": "uuid",
    "createdAt": "2026-11-25T10:30:00.000Z"
}
```

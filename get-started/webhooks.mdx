# Webhooks

Waysdrop sends webhooks for key order and delivery lifecycle events. Webhooks are delivered asynchronously and retried on failure.

## Delivery & signature

Webhook payloads are POSTed to the webhook URL configured for the API key.

### Environments

Webhooks are scoped to the environment of the API key:

- Live: `https://api.waysdrop.com`
- Staging: `https://staging-api.waysdrop.com`

Configure your webhook URL in the matching dashboard:

- Live: https://api-dashboard.waysdrop.com
- Staging: https://staging-api-dashboard.waysdrop.com

### Payload

```json
{
    "event": "delivery.in.transit",
    "data": {}
}
```

### Headers

- `Content-Type: application/json`
- `User-Agent: Waysdrop-Webhook/1.0`
- `X-Webhook-Log-Id: <logId>`
- `x-waysdrop-signature: <hex signature>`

**Idempotency**

Use `X-Webhook-Log-Id` as an idempotency key. The same event may be retried and delivered more than once; you should safely ignore duplicates by storing processed log IDs.

### Signature

`x-waysdrop-signature` is computed as:

- Algorithm: `sha256`
- Secret: your API key value (the same string you send in `api-key`)
- Input: `JSON.stringify({ event, data })`

**Verification example (Node.js)**

```js
import crypto from "crypto";

export function verifyWaysdropSignature({ apiKey, body, signature }) {
    const computed = crypto
        .createHmac("sha256", apiKey)
        .update(body)
        .digest("hex");
    return crypto.timingSafeEqual(
        Buffer.from(computed),
        Buffer.from(signature),
    );
}
```

## Your webhook response

Waysdrop treats any successful `2xx` response as “delivered”. Your endpoint should respond quickly (Waysdrop times out at 5 seconds).

**Recommended response**

```json
{
    "received": true
}
```

Waysdrop stores your response body in the webhook log for debugging (if any).

## Retries and delivery guarantees

Webhooks are delivered asynchronously and retried until one of these happens:

- delivered successfully
- exhausted retry attempts (max: 10)

**Retry conditions**

- Retries on network errors/timeouts.
- Retries on `408` and `429`.
- Retries on all `5xx`.
- Does not retry for other `4xx` responses.

**Backoff**

- `nextRetryAt` uses exponential backoff: `2^attempts` seconds.
- A repeat job runs roughly every 60 seconds and attempts retries once `nextRetryAt` is due.

## Webhook events

All timestamps are serialized as ISO strings.

### Money in webhooks

Money-bearing webhooks follow the [two-layer model](/get-started/money-and-currencies):

| Field pattern                                                 | Meaning                                                                                    |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `totalValue`, `costs.*`, `amount`, `refundAmount`             | **USD catalog / ledger**                                                                   |
| `*Display` companions                                         | Local formatting in your corridor currency: `{ usd, local: { currency, amount, symbol } }` |
| `refundInputAmount`, `refundCurrencyCode`, `fxRateUsdToLocal` | Native wallet credit on cancel (when a refund transaction exists)                          |

Display fields are added server-side at delivery time — you cannot pass `?currency=` on webhooks.

### payment.received

Fired when a customer completes payment via **`POST /api/payments/checkout`**. The amount is credited to your merchant wallet.

```json
{
    "event": "payment.received",
    "data": {
        "reference": "DEP_xxx",
        "merchantReference": "order-48291",
        "amount": "5000.00",
        "amountDisplay": {
            "usd": 3.33,
            "local": { "currency": "NGN", "amount": 5000, "symbol": "₦" }
        },
        "currencyCode": "NGN",
        "amountUsd": "3.33",
        "status": "SUCCESS",
        "walletChannel": "MERCHANT",
        "customerEmail": "customer@example.com",
        "createdAt": "2025-01-01T12:00:00.000Z"
    }
}
```

`merchantReference` is `null` when you did not send one on checkout create. Use `reference` (Waysdrop) for processor reconciliation.
